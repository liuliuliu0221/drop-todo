# M4C 验证记录（2026-08-21）

## 1. 结论

M4C 中不依赖 Apple Developer 资产的发布工程已经完成：版本与构建号、正式 AppIcon、Hardened Runtime、显式沙盒权限、隐私说明、内测说明、Release Archive、DMG、`/Applications` 快捷方式、产物复验、SHA-256 和发布 manifest 均已实现并通过 dry-run。

## 3. 发布流水线

`scripts/m4c_release.sh` 提供两个模式：

- `dry-run`：允许 dirty worktree，以 ad-hoc 签名创建 Archive 和 DMG，验证发布结构，但明确禁止对外分发；
- `signed`：要求 clean worktree，并要求 `M4C_DEVELOPER_IDENTITY`、`M4C_TEAM_ID` 和 `M4C_NOTARY_PROFILE`；使用 Developer ID 导出、提交 notarytool、等待 Accepted、staple 并验证。

两个模式都会：

1. 执行 Release hygiene；
2. 使用 `MARKETING_VERSION` 和 `CURRENT_PROJECT_VERSION` 创建 Release Archive；
3. 检查应用名称、Bundle ID、版本、最低系统和非空 `AppIcon.icns`；
4. 使用 `codesign --verify --deep --strict` 检查代码封装；
5. 检查 Hardened Runtime 签名 flag 和沙盒 entitlements；
6. 生成含“水滴待办.app”、`/Applications` 快捷方式、隐私说明和内测说明的压缩 DMG；
7. 使用 `hdiutil verify` 校验 DMG，重新挂载并复验包内应用；
8. 输出 SHA-256、Commit、worktree 状态、Xcode、签名模式和公证状态 manifest。

`scripts/m4c_verify_app.sh` 可独立验证已构建或已挂载的应用。dry-run 没有分发身份，Xcode 将 `.xcarchive` 归类为 generic archive，这是当前凭据状态下的预期限制。
