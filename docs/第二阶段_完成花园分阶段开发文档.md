## 1. 阶段目标

第二阶段移除鱼缸，把“完成任务”的结果改造成可长期积累的屏幕底部花园：

1. 用户完成任务后，对应水滴从当前位置直接坠向屏幕下边缘；
2. 水滴撞击底边后产生向两侧四溅的水滴粒子；
3. 每个水花粒子的随机落点生成一小簇草；
4. 小草只在首次出现时从零生长到正常高度，不会因为完成次数增加而不断变高；
5. 后续完成任务会增加草簇数量和局部密度，逐步填补空白区域；
6. 长期使用后，草地在视觉上连续覆盖整个屏幕下边缘。

本阶段中的“成长”特指覆盖范围和密度增长，不指草叶高度持续增长。

## 2. 产品行为约定

### 2.1 完成与逾期必须保持不同语义

| 任务结果 | 水滴表现 | 最终结果 |
|---|---|---|
| 完成 | 蓝色水滴坠落并四溅 | 水花落点长出小草 |
| 逾期 | 黑色沥青水滴坠落 | 进入时间废墟，不生成小草 |

现有逾期坠落动画继续保留，不能因完成动画改造而改变废墟语义。

### 2.2 草地密度规则

- 草叶高度固定在设计范围内，例如 `9...18 pt`；不同草叶可有轻微随机差异。
- 新水花落点生成新的草叶或提高对应区域的草簇密度。
- 已有草叶不会随着完成总数持续变高。
- 同一区域达到渲染密度上限后，继续完成任务只增加颜色层次、前后排和覆盖厚度，不无限创建绘制对象。
- “长满”是视觉状态，不要求每个像素都被草叶覆盖。

建议将“视觉长满”定义为同时满足：

- 至少 95% 的底边密度单元拥有草；
- 连续空白区域不超过 24 pt；
- 草叶高度仍保持正常范围，没有形成越来越高的墙。

### 2.3 水花随机规则

每次完成任务产生一次主撞击和 `6...10` 个可见水花落点。每个水花落点只增加 `2` 根草。落点使用带种子的伪随机算法生成，以便测试、重启恢复和问题复现。新草约用 `1.5 秒` 缓慢长到固定高度；已有草叶保持不动，只让本次新增的少量草叶播放生长动画。

建议采用混合分布：

- 65% 近场水花：落在撞击点左右较近范围；
- 25% 中场水花：落在更远位置，扩大局部覆盖；
- 10% 补空水花：从当前低密度区域中随机选择，保证长期使用后能覆盖整条底边。

“补空水花”仍然随机，只是候选范围优先选择较稀疏的区域。若完全使用无偏随机，某些位置可能长期没有草，无法可靠达到“最终长满”的产品目标。

### 2.4 清理与保留规则

- 清除“已完成任务”列表时保留花园，花园代表长期完成积累；
- 执行“清除全部数据”时同时清空花园；
- 删除应用不会自动删除沙盒内花园数据；
- 花园暂不提供单独开关、样式、密度或位置设置；
- 鱼缸显示、隐藏和位置调整设置全部移除。

## 3. 技术可行性结论

当前技术栈可以完成本需求，不需要新增第三方依赖。

继续使用：

- SwiftUI：主窗口、任务管理和设置；
- AppKit `NSPanel`：跨窗口透明覆盖层；
- Core Graphics / `NSBezierPath`：草叶与水花绘制；
- Core Animation（QuartzCore）：短时粒子、生长和淡出动画；
- Metal：继续负责刘海液态水滴，不承担第一版草地渲染；
- Swift 6 并发模型：花园状态服务与持久化；
- JSON 原子写入：花园状态存储与恢复。

暂不引入 SpriteKit。当前效果可以用现有 AppKit 和 Core Animation 完成，引入 SpriteKit 会增加第二套场景、坐标和渲染生命周期。

只有未来需要上千根独立草叶持续受风、真实液体折射或复杂粒子碰撞时，才考虑新增专用 Metal 实例化渲染器或 compute shader。这不属于 0.2.0 范围。

## 4. 总体架构

```text
用户完成任务
    ↓
GardenService 写入待提交种草事件
    ↓
TaskService 原子保存 completed 状态
    ↓
GardenService 提交密度变化并清除待提交事件
    ↓
WindowCoordinator 获取水滴或任务行屏幕坐标
    ↓
CompletionFallOverlayPanel 播放垂直坠落
    ↓
SplashParticleSystem 按已提交落点播放随机水花
    ↓
GardenOverlayPanel 播放新草生长并渲染最新密度
```

任务状态和花园密度必须成功持久化后才能播放动画。动画失败不得回滚已经完成的任务或花园；跨文件写入通过待提交事件完成崩溃恢复。

## 5. 新增模块设计

### 5.1 `CompletionFallOverlayPanel`

职责：

- 创建覆盖当前目标屏幕的透明、无边框、非激活窗口；
- 忽略鼠标事件，不抢焦点；
- 从刘海水滴或任务列表行的屏幕坐标开始动画；
- 水滴基本保持 X 坐标不变，使用重力加速坠落；
- 接近底部时纵向拉长，撞击时压扁；
- 输出标准化撞击位置和撞击时间；
- 屏幕变化、休眠或任务取消时安全停止。

可复用现有 `ExpirationAnimationGeometry` 的拉长与重力曲线，但完成水滴必须使用蓝色主题，并与黑色逾期动画使用不同的请求类型和回调。

### 5.2 `SplashParticleSystem`

职责：

- 根据完成任务 ID、完成时间和撞击点生成稳定随机种子；
- 生成 `6...10` 个水花粒子；
- 每个水花落点只生成 `2` 根新草；
- 为每个粒子生成初速度、方向、重力、尺寸和落点；
- 播放抛物线飞行、缩小和淡出；
- 粒子落地时回调 `GardenService`；
- 动画结束后立即释放粒子，不保留长期节点。

粒子只需要视觉可信，不实现真实流体求解。采用二维抛体公式即可：

```text
x(t) = x0 + vx × t
y(t) = y0 + vy × t - 0.5 × gravity × t²
```

落点必须限制在当前屏幕可用区域内。随机值由固定种子生成，禁止直接依赖不可复现的全局随机状态。

### 5.3 `GardenService`

建议实现为独立 `actor`，职责包括：

- 接收完成事件与水花落点；
- 防止同一任务重复增加草地；
- 更新密度单元；
- 按补空策略生成稀疏区域落点；
- 原子保存花园状态；
- 启动时加载、校验和恢复状态；
- 发布不可变 `GardenSnapshot` 给主线程渲染；
- 执行“清除全部数据”时删除花园状态。

### 5.4 `GardenOverlayPanel`

职责：

- 在当前目标屏幕下边缘显示透明草地层；
- 使用标准化坐标适配分辨率变化；
- 点击穿透，不成为主窗口或键盘焦点；
- 平时停止动画循环，只绘制静态草地；
- 新草出现时短暂播放生长动画；
- 屏幕休眠时完全停止动画；
- 遵循现有全屏隐藏策略；
- 遵循“减少动态效果”设置。

建议初始高度为 `64 pt`，锚定 `NSScreen.visibleFrame.minY`，避免遮挡 Dock。草叶的视觉高度保持在 `9...18 pt`，其余区域用于水花飞行和轻微摆动。

## 6. 数据模型与持久化

建议新增独立文件：

```text
Application Support/WaterDropTodo/garden.json
```

建议模型：

```swift
struct GardenState: Codable, Sendable {
    var schemaVersion: Int
    var totalCompletions: Int
    var cells: [GardenCell]
    var pendingEvents: [PendingGardenEvent]
    var savedAt: Date
}

struct GardenCell: Codable, Sendable {
    var density: UInt16
    var styleSeed: UInt64
    var lastWateredAt: Date?
}

struct PendingGardenEvent: Codable, Sendable {
    var taskID: UUID
    var randomSeed: UInt64
    var cellDeltas: [CellDensityDelta]
    var preparedAt: Date
}
```

第一版固定使用 128 个标准化密度单元：

- 单元索引与屏幕物理分辨率无关；
- `normalizedX = (index + 0.5) / 128`；
- 分辨率变化后无需迁移数据；
- 每个落点增加目标单元密度，并可对相邻单元施加较小增量；
- `density` 可持续累计，但渲染层对可见草叶数量设置上限。

`pendingEvents` 只保存尚未完成跨文件提交的短期事务，正常情况下为空，不随历史完成次数增长。旧版本没有 `garden.json` 时按空花园启动，不修改现有任务数据 Schema。

### 6.1 一致性与补偿

完成任务和花园写入跨两个存储文件，不能假设它们同时成功。采用轻量两阶段提交：

1. `GardenService.prepare(taskID:)` 生成确定性落点并写入 `pendingEvents`，此时不增加密度；
2. `TaskService.complete` 原子保存任务的 completed 状态；
3. 成功后执行 `GardenService.commit(taskID:)`，一次性应用单元增量并移除 pending；
4. 如果任务完成失败，执行 `GardenService.cancel(taskID:)`；
5. 启动时检查残留 pending：任务已完成则提交，任务仍 active 或不存在则取消；
6. 恢复过程只更新静态草地，不重新播放坠落和水花动画。

同一任务只能存在一个 pending 事件，`prepare` 和 `commit` 都必须幂等。该方案让 Garden JSON 保持固定规模，避免保存所有历史任务 UUID。

## 7. 随机分布与最终覆盖算法

### 7.1 确定性随机种子

每个完成事件的种子由以下字段计算：

```text
taskID + completedAt + gardenSchemaVersion
```

同一任务在相同状态下始终产生相同落点，便于测试和故障恢复。

### 7.2 密度权重

补空落点从所有单元中按以下权重采样：

```text
weight(cell) = 1 / (1 + density)²
```

密度越低，被选择的概率越高，但仍保留随机性。

### 7.3 渲染密度

每个单元的可见草叶数量建议为：

```text
visibleBlades = min(2 + density × 2, 12)
```

当密度超过可见上限时，不再创建更多草叶对象，而是通过前后层、颜色深浅和横向交叠表现更浓密的草簇。

整个草地建议限制在约 1,200 个可见草叶以内，避免长期使用后绘制成本持续增长。

## 8. 动效与无障碍策略

### 8.1 标准动画

建议单次完成动画时长：

| 阶段 | 建议时长 |
|---|---:|
| 水滴拉长与坠落 | 0.55–0.75 秒 |
| 撞击压扁 | 0.08–0.12 秒 |
| 水花抛射 | 0.35–0.55 秒 |
| 新草生长 | 0.30–0.45 秒 |

多任务快速完成时进入队列，每个完成事件间隔约 `0.12 秒`，最多同时显示 3 次水花，避免遮满屏幕。

### 8.2 减少动态效果

系统开启“减少动态效果”时：

- 水滴使用较短的淡入坠落或直接移动到底部；
- 取消大幅抛物线水花；
- 在计算出的随机落点显示轻微闪烁；
- 小草在 0.15 秒内淡入，不进行弹性伸展。

### 8.3 性能策略

- 没有新动画时不运行 60 FPS 定时器；
- 草地静态时只在状态或屏幕变化后重绘；
- 粒子动画结束后释放全部临时对象；
- 草叶根据密度单元批量绘制，不为每根草创建独立 `NSView`；
- 后台、休眠和屏幕锁定时停止所有动画。

- 实现近场、中场和补空落点采样；

- 实现 `prepare/commit/cancel` 两阶段提交和启动补偿。

- 所有落点位于 `0...1` 标准化范围；
- 每次完成后覆盖率或密度单调不减；
- 重复处理同一任务不会重复种草；
- 存储损坏时可恢复或保留损坏副本；
- 完成列表清理后花园仍保留，清除全部数据后花园归零。

### M5C：完成水滴坠落与水花动画

目标：完成任务后播放新的坠落、撞击和四溅动画。

开发内容：

- 新增 `CompletionFallOverlayPanel`；
- 从刘海水滴和任务列表行读取正确的屏幕起点；
- 实现垂直重力坠落和撞击压扁；
- 新增 `SplashParticleSystem`；
- 将算法生成的落点映射为可见抛物线；
- 为水花落地提供回调；
- 支持连续完成动画队列；
- 支持屏幕变化、休眠、全屏和减少动态效果。

退出条件：

- 完成任务不再飞向鱼缸；
- 水滴到达目标屏幕下边缘，落点误差不超过 1 pt；
- 每次完成产生 `6...10` 个随机水花落点，每个落点只增加 `2` 根新草；
- 快速完成多个任务不会丢失完成状态或永久残留覆盖窗口；
- 动画窗口始终点击穿透且不抢焦点。

### M5D：屏幕底部草地渲染与密度成长

目标：水花落点长出小草，草地随完成次数变密并持久显示。

开发内容：

- 新增 `GardenOverlayPanel` 和 `GardenCanvasView`；
- 根据 128 个密度单元批量绘制草叶；
- 实现每个水花落点的新草生长动画；
- 鼠标接触草叶时扰动附近草簇，离开后平滑回弹，且不拦截 Dock 点击；
- 每根新草以 `2%` 固定概率开出稀有小花，花型在五瓣圆花、小雏菊、铃铛花和蒲公英点簇中稳定随机，不提供用户设置；
- 保持草叶高度在固定范围；
- 实现密度上限、前后排和颜色变化；
- 处理屏幕尺寸、缩放比例和 Dock 位置变化；
- 启动时加载静态花园；
- 草地无动画时停止刷新循环。

退出条件：

- 第一次完成后至少一个随机落点长出草簇；
- 连续完成只增加密度和覆盖，不使草叶持续变高；
- 重启应用后草地位置和密度保持一致；
- 500 次模拟完成后可见对象数量仍受上限约束；
- 花园不影响鼠标点击、Dock 和其他窗口焦点。

### M5E：覆盖收敛、兼容与体验完善

目标：确保长期使用后能够可靠形成完整草带。

开发内容：

- 调整补空采样权重和覆盖速度；
- 建立 10、50、100、250、500 次完成的视觉快照；
- 验证达到视觉长满后的继续完成表现；
- 处理无刘海、屏幕切换、合盖、唤醒和分辨率变化；
- 更新设置、菜单、欢迎页和 README 中的鱼缸文案；
- 增加本地诊断事件，但不记录任务名称和具体草地坐标；
- 检查旧版本任务数据升级兼容。

退出条件：

- 模拟长期完成后覆盖率达到至少 95%；
- 最大连续空白不超过 24 pt；
- 草叶高度分布不随完成总数上移；
- 无刘海环境不崩溃，主任务数据仍可读取；
- Reduce Motion、休眠和全屏行为符合策略。

### M5F：质量门禁与 0.2.0 发布验证

目标：达到可进入第二阶段内测的质量标准。

## 13. 风险与控制

| 风险 | 控制措施 |
|---|---|
| 完全随机导致长期存在空白 | 对低密度单元增加随机权重 |
| 完成次数增长导致对象无限增加 | 固定密度单元和可见草叶上限 |
| 跨文件写入中退出导致少种草或重复种草 | pending 两阶段提交、任务 ID 幂等和启动补偿 |
| 草地遮挡 Dock 或点击 | 锚定 visibleFrame、透明且点击穿透 |
| 多次完成造成粒子过载 | 动画队列、最多 3 组并发、粒子及时释放 |
| 减少动态效果用户不适 | 提供淡入式简化动画 |
| 屏幕变化导致位置漂移 | 全程保存标准化坐标和密度单元 |
| 旧鱼缸状态残留 | 删除入口并忽略旧 aquarium UserDefaults |

## 14. 阶段完成定义

M5 只有同时满足以下条件才算完成：

- 鱼缸代码、入口、设置和测试全部移除；
- 完成水滴会坠落、四溅，并在随机落点生成小草；
- 小草随完成次数变密而不是变高；
- 长期模拟后草地能连续覆盖整个屏幕下边缘；
- 花园跨重启持久化且不会重复种草；
- 完成、逾期、召回和焚毁数据语义保持正确；
- 点击穿透、焦点、全屏、休眠和减少动态效果行为通过验证；
- 性能和内存不会随历史完成次数无限增长；
- Release 与 DMG dry-run 流水线通过。
