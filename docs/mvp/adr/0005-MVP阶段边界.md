# ADR 0005：MVP 阶段边界

- 状态：已采纳
- 日期：2026-08-19

## 背景

早期文档把时间状态校正、逾期视觉和完整废墟业务混在同一阶段，容易让数据正确性依赖后期动画实现。

## 决定

- M0A～M0D：工程基线、刘海窗口与命中、Metal、跨窗口动画验证。
- M1A～M1C：领域/JSON/TimeEngine、应用外壳/快速创建、主窗口/可靠性。基础 `active → ruined` 必须在 M1 正确持久化。
- M2A～M2C：真实刘海渲染、悬停保护、主动完成与鱼缸。
- M3A～M3C：在线到期视觉与废墟、召回/焚毁、设置/导出/屏幕能力暂停。
- M4A～M4C：质量门禁、性能兼容、签名分发与内测。
- 当前执行优先级：POC v1.1 → MVP 文档 → PRD v2.0 → 技术选型报告 v1.0。

## 影响

到期状态不等待 M3，也不依赖坠落动画。M3 复用 M1 的 `TimeEngine`，只增加在线快照、动画和废墟交互。

## 备选方案

曾考虑把 TimeEngine 和基础到期转换留到 M3。该安排会让 M1/M2 长期保留已过期的 active 任务，也使数据正确性依赖视觉阶段，因此未采纳。

## 回滚条件

只有前一阶段的退出条件无法独立验证，或实机证据表明边界造成不可接受的重复实现时，才通过新 ADR 调整阶段。
