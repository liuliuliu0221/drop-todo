## 3. 总体技术架构

### 3.1 技术栈总表

| 层 | 选型 | 理由 |
|---|---|---|
| 语言/UI | Swift 5.9+，SwiftUI 为主 + AppKit 窗口管理 | SwiftUI 快速构建列表/设置/卡片；NSPanel 等folk窗口能力必须 AppKit |
| 最低版本 | macOS 13.0 Ventura | 决策 #6；刘海机出厂 ≥ macOS 12，13+ 覆盖现役设备；放弃 SwiftData（需 14+）换取 |
| 依赖管理 | SPM | 全部依赖支持 SPM，无 CocoaPods 必要性 |
| 持久化 | JSON 文件（Codable）+ 原子写 | 数据量级小（活跃 ≤ 数十 + 归档）；可迁移 GRDB |
| 渲染 | TimelineView + Canvas（metaball 距离场）；必要时升级 Metal fragment shader | 刘海区域 ≈ 200×38pt，Canvas 逐像素可承受；NotchDrop 证明 Metal 上限够用 |
| 分发 | Developer ID + Notarization + Sparkle 2 | 决策 #7；不上架则无沙盒约束 |

### 3.2 应用形态与窗口拓扑

`LSUIElement = true`（无 Dock 图标），`MenuBarExtra` 菜单栏入口：

```
App
├── 刘海液池窗口    NotchPanel: .screenSaver 层级 / canJoinAllSpaces+stationary+fullScreenAuxiliary
├── 快速输入窗口    NSPanel: .floating，居中，Esc 关闭，回车创建
├── 鱼缸浮窗       NSPanel: .floating + .ignoresMouseEvents 可切换，拖动记忆位置
└── 主窗口        普通 SwiftUI Window：任务列表 + 时间废墟侧栏 + 设置 Tab
```

### 3.3 数据模型（初稿）

```swift
struct Task: Codable, Identifiable {
    let id: UUID
    var title: String
    var deadline: Date
    var tag: Tag?              // 工作/生活/灵感
    var urgency: Urgency       // high / medium / low（PRD §6.2）
    var state: TaskState       // active / ruined / recalled / completed
    var createdAt: Date
    var completedAt: Date?
    var ruinedAt: Date?        // 进入废墟时间（算逾期时长）
}

enum Urgency: Int, Codable { case low, medium, high }
```

水滴位置函数（PRD §6.2）：`x = w · (0.35 + 0.65·(1 - timeRatio)·(0.6 + 0.4·urgencyWeight))`，具体系数 POC 调参。

## 4. 关键技术决策详述

### 4.1 为什么 Canvas/Metaball 而不是 SpriteKit / Metal / Lottie

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Canvas + metaball 距离场** ✅ | 零依赖；水滴-液面连续连接、垂坠、断开全部是 metaball 天然特性；参数化调色（清透→深蓝→沥青）容易 | 极端质感（折射/焦散）需升级 | **MVP 采用** |
| Metal shader（ColorfulX） | 上限高，NotchDrop 已验证 | 引入依赖与调试成本；200×38pt 区域杀鸡用牛刀 | 质感不达标时升级 |
| SpriteKit | 物理引擎现成 | 整个 App 只有一处用得上；场景/节点模型过重 | 否决 |
| Lottie/AE 动画 | 美术可控 | 状态连续插值（位置=时间函数）难以预制；boring.notch 只用于点缀动画 | 否决（水滴），可选（焚毁特效） |

Metaball 原理备忘：场函数 `F(p) = Σ rᵢ²/|p - cᵢ|²`，阈值等值线即液面轮廓——两球接近时自然融合成"渗出的垂坠"，拉开时自然断开坠落，与 PRD §3.1/§3.2 的描述一一对应。

### 4.2 中文自然语言时间解析：自研规则引擎

- **不引入** SwiftyChrono（无中文支持）；**不移植** ChineseTimeNLP（无 License，且有 Python 依赖）。
- 自研范围（PRD 示例 + 高频表达）：
  - 相对量：「2 小时后」「半小时后」「30 分钟后」「3 天后」
  - 今日段：「今晚 8 点」「下午 3 点」「中午 12 点」「早上 9 点」
  - 明确日：「明天 18:00」「后天下午 4 点」「周二上午 10 点」「下周一 9 点」「8 月 20 号」
  - 兜底：ISO/常规格式 `2026-08-20 14:00`、`14:00`
- 解析成功 → 回显完整日期时间（PRD §5.1 的确认机制就是容错层）；失败 → 内联提示 + 手动日期选择器。
- 规则表驱动，方便单测（`DateParserTests` 覆盖 ≥ 30 条用例）。

### 4.3 悬停交互

- 刘海窗口透明但需要鼠标命中：水滴区域用 `NSTrackingArea`/SwiftUI `onHover` 命中检测；整窗 `ignoresMouseEvents = false` 但仅水滴形状区域响应（透明区域点击穿透用 `NSWindow` 的 nonopaque + hit-test 裁剪实现）。
- 悬停 = 渲染层提高该球半径（放大且保持液面连接）+ 光晕（`shadow(color:radius:)` 等价 Canvas glow）。
- 倒计时冻结：`TaskStore` 的 tick 定时器对该任务 `isFrozen` 标记，deadline 计算用 `frozenAt` 快照偏移补偿（PRD §5.2：移开后恢复，不能瞬间跳变——冻结期间流逝的时间需补偿到真实 deadline，POC 验证手感）。

### 4.4 触觉与点击反馈

- `NSHapticFeedbackPerformer.perform(.generic)`（触控板 Force Touch 类反馈）；无触觉设备 → `withAnimation` 视觉抖动（PRD §5.6）。
- 连点 10 次：`@State clickCount` + 1 秒超时 `DispatchWorkItem` 重置；每次点击在水滴 Canvas 上叠加裂纹路径（预生成 10 条随机贝塞尔裂纹，按进度显示）。

### 4.5 存储与性能

- 写入时机：状态转换时立即写（数据量 KB 级，无性能问题）；`FileManager` 原子替换写。
- 定时 tick：活跃任务存在时 `Timer.publish(every: 1s)` 驱动重绘；全部完成/废墟时降频到 0（Canvas TimelineView 仅在有活跃任务时运行）。
- 鱼缸常驻动画：`TimelineView(.animation(minimumInterval: 1/30))` 限帧 30fps，能耗可控；"减少动态效果"开启时金鱼静止为静态图 + 微摆。

## 7. POC 计划（M0，约 1~1.5 周）

对应 PRD"建议开发顺序"：先验证可行性，再做闭环。

| 序 | 验证项 | 通过标准 |
|---|---|---|
| P1 | 刘海窗口：定位、透明、`.screenSaver` 层级、`.fullScreenAuxiliary` | 5 类全屏应用（Safari 视频/Keynote/Xcode 全屏/游戏窗口/Finder）下均正常显示 |
| P2 | 鼠标命中与穿透 | 水滴可悬停触发放大，周围透明区点击落到下层应用 |
| P3 | Canvas metaball 液池 | 1 液面 + 3 水滴连续渲染 ≥ 60fps；悬停放大、双色过渡、拉断坠落动画成立 |
| P4 | 中文时间解析冒烟 | PRD 示例 + 20 条高频表达全部正确解析 |

P1–P4 全过 → 进入 M1（输入框 + 存储 + 刘海水滴实时化）→ M2（悬停卡 + 完成汇入鱼缸 + 逾期坠落）→ M3（废墟/召回/焚毁/设置/Sparkle）。
