## 1. 文档目的

本 POC 不是一次性技术演示，而是一个可以分发给内测用户、连续日常使用的最小闭环版本。它需要同时验证：

1. 用户是否愿意让任务长期停留在刘海区域；
2. 水滴的位置、颜色和形态是否能传达时间压力；
3. 创建、查看、完成、逾期、召回和焚毁能否形成完整且稳定的使用循环；
4. 刘海窗口、透明命中、跨屏动画和本地数据在真实 macOS 环境中是否可靠；
5. 常驻动画是否足够安静，并能维持可接受的能耗。

POC 通过后，才评估视觉精修以及其他非 MVP 能力；自然语言解析、自动更新和更广泛兼容性均不在当前承诺范围内。

## 2. POC 成功标准

满足以下条件时，POC 才视为通过：

- 内测用户可以独立完成完整任务生命周期，不需要开发者协助修复数据；
- 连续 7 天日常使用中没有任务丢失、状态错误或阻断使用的崩溃；
- 8 个可见水滴下，悬停目标仍可识别、可选择，时间表达没有明显歧义；
- 全屏、睡眠唤醒、应用重启和系统时间变化后，任务状态能恢复正确；
- 常驻状态不会持续高帧率空转，能耗达到本文件第 12 节的门槛；
- 安装包可以在干净的 macOS 13+ 测试环境中通过 Gatekeeper 正常安装和启动；
- 无 P0/P1 级未解决缺陷，核心体验的内测反馈达到第 14 节的退出条件。

## 3. 范围

### 3.1 必须实现

- 仅在带内置刘海屏的 Apple Silicon MacBook 上启动主流程；
- 菜单栏常驻应用，无 Dock 图标；
- 默认全局快捷键 `⌥T`，并支持重新录制；
- 事件名称与时间分离的快速创建窗口；
- 快捷时间选项和自定义日期时间选择器；
- 工作、生活、灵感三个固定标签；
- 低、中、高三档重要程度；
- 进行中、时间废墟、已完成、设置四个主窗口区域；
- 进行中任务的编辑、完成和取消；
- 刘海液池、最多 8 个可见水滴、时间颜色和重要程度长度；
- 悬停放大、光晕、任务卡、卡片锁定和完成入口；
- 完成水滴直线飞入鱼缸；
- 逾期坠落、时间废墟、连点 10 次召回和彻底焚毁；
- 可显示、隐藏、移动并记忆位置的鱼缸；
- 三条低动态金鱼和完成时的短时快速反馈；
- 单屏刘海模式、全屏模式和多显示器降级处理；
- 睡眠唤醒、应用重启、系统时间或时区变化后的状态校正；
- 本地持久化、备份恢复、数据导出和本地诊断日志；
- Developer ID 签名、公证及 DMG 内测分发。

### 3.2 明确不实现

- 中文或其他自然语言时间解析；
- 在一句话中同时提取任务名称和截止时间；
- Sparkle 或其他自动更新机制；
- App Store 上架；
- 账号、云同步、团队协作和跨设备同步；
- 系统通知、声音提醒和后台推送；
- 多显示器刘海渲染、外接屏顶部胶囊或跨屏迁移；
- 自定义标签、重复任务、子任务、任务依赖和日历集成；
- 搜索、批量操作、统计报表和复杂排序；
- 鱼缸喂养、成长、金币、等级或其他养成系统；
- 应用内独立的动画强度或“减少动态效果”设置；
- 自动遥测或自动上传崩溃报告；
- Intel Mac、无刘海 Apple Silicon Mac 以及 x86_64 构建；

## 4. 首次启动与应用生命周期

### 4.1 首次启动

首次启动显示一次简短欢迎页，内容包括：

- 任务仅保存在本机；
- 默认快捷键为 `⌥T`；
- POC 的刘海水滴仅在单显示器环境中显示；
- 鱼缸位置可通过菜单栏进入调整模式；
- 应用关闭主窗口后仍驻留菜单栏。

完成欢迎页后自动打开快速创建窗口。欢迎页完成状态保存在设置中，后续启动不再显示。

### 4.2 常驻行为

- 应用使用 `LSUIElement = true`，不显示 Dock 图标；
- 后续启动只显示菜单栏入口和鱼缸，不自动打开主窗口；
- 关闭主窗口不会退出应用；
- 退出应用时保留全部任务，下次启动按真实时间重算状态；
- 开机启动默认关闭，由用户主动开启。

### 4.3 菜单栏

菜单栏图标打开菜单，不直接打开主窗口。菜单至少包含：

- 新建任务；
- 打开主窗口；
- 显示或隐藏鱼缸；
- 调整鱼缸位置；
- 设置；
- 退出。

菜单栏入口同时显示进行中任务总数和最近一项截止时间。无进行中任务时不显示截止时间。

## 5. 创建任务

### 5.1 打开方式

- 默认全局快捷键为 `⌥T`；
- 用户可以在设置中重新录制；
- 快捷键冲突时必须显示明确提示，不得静默失败；
- 快速创建窗口已经打开时，再次按快捷键只聚焦现有窗口；
- 用户也可以从菜单栏选择“新建任务”。

### 5.2 输入结构

事件与时间必须分开输入，不提供自然语言解析。

| 字段 | 规则 |
|---|---|
| 事件名称 | 必填；去除首尾空格后 1～100 个字符 |
| 截止时间 | 必填；由快捷选项或自定义选择器设置 |
| 标签 | 选填；工作、生活、灵感；每项任务最多一个 |
| 重要程度 | 必填；低、中、高；默认中 |

打开窗口后，焦点直接进入事件名称。

### 5.3 时间选项

固定快捷选项如下：

- 30 分钟后；
- 1 小时后；
- 2 小时后；
- 今晚 20:00；
- 明天 09:00；
- 自定义。

补充规则：

- “今晚 20:00”只在当天 20:00 前可选；超过后置灰，不自动解释为明晚；
- “明天 09:00”表示下一个自然日的 09:00；
- 自定义选择器精确到分钟；
- 截止时间必须至少晚于当前时间 1 分钟；
- 选择成功后必须回显完整日期、星期和时间；
- 时间默认不选，防止连续按回车误建任务。

### 5.4 键盘和提交

- `Tab` 在输入区域间移动；
- 方向键选择时间选项；
- `Enter` 创建任务；
- `Esc` 关闭窗口；
- 缺少名称或时间时，`Enter` 不创建，并在对应区域显示内联错误；
- 创建成功后立即持久化，关闭窗口并显示轻微视觉确认；
- 关闭未提交窗口时不保存草稿。

## 6. 主窗口与任务管理

### 6.1 信息架构

主窗口包含四个区域：

1. 进行中；
2. 时间废墟；
3. 已完成；
4. 设置。

### 6.2 进行中

- 默认按截止时间升序排列；
- 支持按固定标签筛选；
- 每项任务提供编辑、完成和取消入口；
- POC 不提供搜索、批量操作和用户自定义排序。

### 6.3 编辑

- 只有进行中任务可以编辑；
- 可修改名称、截止时间、标签和重要程度；
- 时间选项及校验与创建任务一致；
- 保存新截止时间时，以保存时刻作为新的视觉起点；
- 修改重要程度后，只重新计算水滴纵向长度；
- 保存后重新排序，并重新选择刘海中可见的 8 个任务；
- 因编辑进入或离开前 8 的任务只做淡入淡出，不播放完成或坠落动画；
- 取消编辑不保存修改；
- 废墟任务必须先召回，不能直接编辑；
- 已完成任务只读。

### 6.4 完成

任务可以从悬停卡片或进行中列表主动完成。两种入口语义相同：

- 先将完成状态持久化，再播放动画；
- 任务进入已完成记录，不进入时间废墟；
- 动画中退出或崩溃时，下次启动仍应保持已完成状态。

### 6.5 取消任务

- 取消入口只出现在任务列表，不出现在悬停卡片；
- 取消前必须二次确认；
- 取消后从本地删除；
- 不进入鱼缸或时间废墟；
- 不播放完成或坠落动画；
- 已到期任务不能取消，只能召回或焚毁。

### 6.6 已完成

- 按完成时间倒序展示；
- 记录只读，不支持重新打开；
- 默认永久保存在本机；
- 用户可以执行“清除完成记录”，操作前必须二次确认；
- POC 不提供完成统计。

## 7. 刘海液池与时间视觉

### 7.1 可见任务

- 最多显示 8 个截止时间最近的进行中任务；
- 其余任务只在主窗口中显示，但仍正常计时和转换状态；
- 可见任务完成、逾期、取消或修改截止时间后，自动补入下一项；
- 正在悬停或已锁定卡片的任务暂时保持稳定，不在交互中途换位；
- 可见集合变化使用淡入淡出，不使用坠落或汇流动画。

### 7.2 剩余时间颜色

颜色仅使用 `remainingTime = deadline - now`，不再使用任务开始时间或生命周期比例。固定色阶如下：

| 剩余时间 | colorProgress | 视觉语义 |
|---|---:|---|
| 24 小时以上 | 0.02 | 非常浅蓝 |
| 12～24 小时 | 0.10 | 浅蓝 |
| 6～12 小时 | 0.20 | 较浅蓝 |
| 3～6 小时 | 0.32 | 中浅蓝 |
| 1～3 小时 | 0.46 | 中蓝 |
| 30～60 分钟 | 0.62 | 较深蓝 |
| 30 分钟以内 | 0.82 | 最深档，仍比旧版浅 |

规则解释：

- 水滴从左到右按截止时间降序排列，越靠右一定越早到期；
- 任务之间使用由任务 ID 稳定生成的非等距间隔，不随每秒刷新抖动；
- 颜色只由剩余时间档位决定，同一档颜色一致；
- 更早到期任务的颜色等级必须与更晚任务相同或更深，不能出现左深右浅；
- 重要程度只影响液滴纵向长度：低约 10pt、中等约 18pt、高约 25pt；
- 三档水滴使用同一个顶部液面连接点，长度变化通过移动中心位置向下延伸，短水滴不能悬空；
- 随时间流逝，颜色只在跨过档位边界时单向加深；
- 修改截止时间后立即按新的剩余时间重新确定颜色；
- `visualStartAt` 可以为数据兼容继续保存，但不参与刘海颜色计算；
- 修改重要程度只允许长度立即变化；
- 召回后的新任务同样只按新截止时间确定颜色。
- 悬停水滴的水平半径和纵向长度统一放大到 `2.0×`，任务身份与命中目标保持不变。

系数允许在 POC 视觉调试阶段微调，但不得破坏以上产品语义。

### 7.3 布局与命中

- 水滴保持与同一片刘海液面连续连接；
- 当前机型的 180pt 实体刘海采用左侧 2pt、右侧 1pt 内缩，有效液面宽度为 177pt；右侧边界保持不变；
- 按 deadline 降序从左到右分配稳定的非等距横向位置；
- 任意情况下更早到期的任务都不能排在更晚到期任务左侧；
- 位置只由可见任务身份与截止时间顺序决定，时间进度刷新不能引起横向抖动；
- 相邻中心最少保持约 19pt 间距，8 项时允许自动收紧随机差异；
- 水平半径在 1～3、4～5、6～8 项时分档缩小，命中范围保持不变；
- 水滴视觉区域可以较小，但每项必须拥有更大的透明命中区域；
- 命中区域重叠时，选择中心距离指针最近的水滴；
- POC 必须在 8 个水滴同时可见时验证可选择性，不能只用 3 个水滴验收。

### 7.4 悬停卡片

- 指针进入扩大命中区域约 150ms 后展开卡片；
- 选中水滴在保持液面连接的前提下放大并产生柔和光晕；
- 卡片优先显示在右侧，空间不足时显示在左侧；
- 水滴与卡片之间设置连续的透明交互走廊；
- 指针离开水滴、走廊和卡片约 250ms 后关闭；
- 点击水滴可以锁定卡片；
- 点击卡片外部或按 `Esc` 解除锁定；
- 同时最多显示一张任务卡；
- 卡片展示名称、分钟级剩余时间、完整截止时间、标签和重要程度；
- 卡片唯一操作按钮为“完成”。

### 7.5 悬停保护期

- 悬停后冻结卡片显示的倒计时和水滴坠落动画，不修改保存的截止时间；
- 悬停开始时任务尚未到期，用户获得最多 60 秒操作保护；
- 保护期内，即使真实截止时间已经经过，点击“完成”仍算主动完成；
- 保护期超过 60 秒后，卡片显示“已到期”，完成按钮禁用；
- 指针移开或解除锁定后，执行逾期坠落并进入时间废墟；
- 保护期只存在于当前运行会话，不写入持久化数据。

## 8. 完成动画与鱼缸

### 8.1 直线汇入动画

- 从悬停卡片完成时，水滴从刘海中的当前位置脱离；
- 从任务列表完成时，在对应任务行生成水滴；
- 水滴沿直线飞向鱼缸水面中的目标点；
- 飞行时间约 0.6～0.9 秒，先轻微加速，接近目标时减速；
- 动画由全屏透明且不接收鼠标事件的过渡窗口承载；
- 动画不能抢占焦点或阻断下层应用交互；
- 鱼缸隐藏时不播放跨屏动画，水滴在原位置淡出；
- macOS 开启“减少动态效果”时，取消跨屏飞行，只做淡出和鱼缸轻微高亮；
- 全程不播放声音。

### 8.2 鱼缸窗口

- 默认位于主屏幕右下角，建议尺寸约 `180 × 110 pt`，边距 16pt；
- 默认显示且点击穿透，不抢占焦点；
- 菜单栏“调整鱼缸位置”进入位置调整模式；
- 调整模式暂时关闭点击穿透，允许拖动并显式完成调整；
- 记忆最后位置；屏幕尺寸变化后自动约束回可见区域；
- 菜单栏和设置均可显示或隐藏鱼缸；
- 固定三条小金鱼，不支持点击、选择、喂养或其他操作。

### 8.3 金鱼动画

- 平时保持低频、缓慢游动；
- 水滴落入时，距离落点最近的金鱼快速游向落点；
- 约 1 秒后恢复低频游动；
- 隐藏、屏幕休眠或退出应用时停止渲染；
- macOS 开启“减少动态效果”时，不执行快速游动；
- 应用内不提供独立的动画效果开关。

## 9. 逾期、废墟、召回与焚毁

### 9.1 逾期坠落

- 截止时间到达且没有有效悬停保护时，水滴到达最右侧并变成黑色；
- 使用约 0.6 秒完成拉长、断开和坠落；
- 领域状态先转为废墟，再以临时渲染快照播放坠落动画；
- 动画结束后任务出现在时间废墟；
- 逾期时长始终按“当前时间 − 原截止时间”计算；
- 应用退出或 Mac 睡眠期间到期的任务，在下次启动或唤醒时直接进入废墟，不补播过时动画；
- 多个任务同时到期时依次坠落，间隔约 0.2 秒；
- 一次恢复出大量逾期任务时全部直接归档；
- 不发送系统通知或播放声音。

### 9.2 时间废墟

每项废墟任务展示：

- 任务名称；
- 原截止时间；
- 实时逾期时长；
- 召回入口；
- 彻底焚毁入口。

### 9.3 连点 10 次召回

- 必须连续点击同一任务 10 次；
- 相邻点击超过 1 秒或点击其他任务时，进度清零；
- 每次点击增加一道裂纹；
- 有触觉能力时提供轻微触觉，否则使用视觉震动；
- 第 10 次后，在当前行展开与创建任务相同的时间选项；
- 用户确认新截止时间后，创建新的进行中任务；
- 新任务保留原名称、标签和重要程度；
- 原逾期记录转为内部召回历史，不再显示于时间废墟；
- 新旧任务通过 `recalledFromID` 建立关系；
- 用户取消时间选择时，任务恢复普通废墟状态，连点进度清零。

### 9.4 彻底焚毁

- 焚毁前必须二次确认，并明确提示无法恢复；
- 确认后删除当前废墟任务及其内部召回关系；
- 已经由它召回产生的新任务不受影响；
- 如果新任务仍保留关联字段，应在删除时清除悬空关联。

## 10. 屏幕环境与系统行为

### 10.1 单显示器

- 仅连接一块带刘海的内置屏幕时，正常显示刘海水滴；
- 刘海几何变化或分辨率变化后重新定位；
- 不得使用固定像素坐标假设所有机型刘海尺寸相同。

### 10.2 多显示器与镜像

- 检测到外接显示器、镜像，或合盖仅使用外接屏后，暂停整个刘海水滴窗口；
- 菜单栏显示“多显示器模式暂未适配”；
- 任务计时、主窗口、鱼缸、完成和废墟功能继续工作；
- 恢复单屏后自动重新显示刘海水滴，并按真实时间刷新状态；
- POC 不尝试在多显示器之间迁移水滴窗口。

### 10.3 无刘海设备

- 无刘海设备不属于产品支持范围；
- 启动时显示明确的“不受支持”提示，然后安全退出；
- 不提供顶部胶囊，也不继续运行任务列表、快速创建、鱼缸或废墟功能；
- Intel Mac 与 x86_64 构建同样不在 POC 范围内。

### 10.4 全屏

- 全屏应用前台时默认继续显示刘海水滴；
- 设置中提供“全屏时隐藏水滴”开关，默认关闭；
- 隐藏只影响水滴窗口，不暂停计时和状态转换；
- 重新退出全屏后恢复水滴并按真实时间刷新；
- 必须通过实机 POC 验证，不把 `.fullScreenAuxiliary` 视为所有应用中的显示保证。

### 10.5 时间与生命周期校正

以下事件发生时，时间引擎必须基于绝对时间重新计算，而不是依赖 Timer 补发：

- 应用启动；
- Mac 睡眠唤醒；
- App 重新激活；
- 系统时间发生显著变化；
- 时区变化；
- 显示器配置恢复为单屏。

### 11.1 技术栈

| 层 | POC 选型 |

| 普通 UI | SwiftUI |
| 窗口管理 | AppKit / NSPanel |
| 液体渲染 | 原生 Metal fragment shader，使用 MTKView 或 SwiftUI 包装层 |
| 普通矢量效果 | SwiftUI Canvas / Path |
| 持久化 | Codable JSON，版本化封装和原子写入 |
| 快捷键 | KeyboardShortcuts 3.0.1（唯一第三方依赖，精确锁定） |
| 开机启动 | 原生 SMAppService |

POC 不使用 Canvas 承担未定义的“逐像素距离场”计算。metaball 场函数由 Metal fragment shader 计算，Canvas 仅用于裂纹、普通路径和静态装饰。

### 11.2 窗口拓扑

```text

├── MenuBarEntry
├── NotchRenderPanel           刘海液池渲染，全程忽略鼠标
├── DropletHitPanel × 0...8    每个可见水滴的最小透明命中窗口
├── HoverCardPanel/View        任务卡及完成按钮
```

### 11.4 持久状态与临时状态分离

持久状态建议为：

```swift
enum TaskStatus: String, Codable {
    case active
    case ruined
    case completed
    case recalled
}
```

取消和焚毁表示删除记录，不作为长期状态。悬停、锁定、完成汇流、坠落和裂纹进度属于临时展示状态，不写入任务状态：

```text
hovered / pinned / completing / falling / cracking
```

这样可以保证动画过程中崩溃或退出后，领域数据仍处于确定状态。

### 11.5 数据模型最小字段

```swift
struct TaskRecord: Codable, Identifiable {
    let id: UUID
    var title: String
    var deadline: Date
    var tag: TaskTag?
    var urgency: Urgency
    var status: TaskStatus
    var createdAt: Date
    var visualStartAt: Date
    var completedAt: Date?
    var ruinedAt: Date?
    var recalledAt: Date?
    var recalledFromID: UUID?
}
```

逾期时长使用 `Date.now - deadline`，不能使用 `ruinedAt` 替代原截止时间。

### 11.6 时间驱动与刷新频率

- 任务状态始终由绝对 `Date` 推导，Timer 只负责触发 UI 刷新；
- 常驻水滴位置和倒计时以低频刷新；
- 静态或缓慢液体效果不得长期以 60fps 空转；
- 悬停放大、坠落和汇入等短动画期间可临时提升到屏幕刷新率；
- 鱼缸平时低帧率，完成反馈期间临时提速；
- 没有可见动画时停止 TimelineView 或显示链路。

## 12. 数据、隐私与诊断

### 12.1 本地数据

- 不建立账号；
- 不上传任务；
- 数据存放在 `Application Support/<BundleID>/`；
- 路径通过 `FileManager.applicationSupportDirectory` 获取并在沙盒容器内创建，不硬编码绝对路径；
- 覆盖安装 App 不得删除任务数据；
- 数据文件使用包含 `schemaVersion` 的封装结构；
- 所有写入由单一 Actor 或等价串行机制协调；
- 使用临时文件和原子替换；
- 成功写入前保留上一版备份；
- 主文件损坏时尝试恢复备份并通知用户；
- 数据迁移失败时不得覆盖原始文件。

### 12.2 导出与清除

- 用户可以主动导出完整任务 JSON；
- 用户可以主动导出诊断日志；
- 两类导出均通过 `NSSavePanel` 取得用户选择位置的沙盒授权；
- POC 不支持数据导入；
- “清除全部数据”必须二次确认；
- 清除后同时移除任务、历史和备份，不移除应用本身。

### 12.3 诊断日志

- 不接入自动统计或自动崩溃上报；
- 本地日志记录应用版本、系统版本、任务 ID、状态变化和错误；
- 默认不记录任务名称；
- 最多保留 7 天；
- 只有用户主动导出后，日志才会离开设备。

| 取消任务 | 未定义 | 任务列表中允许二次确认后取消 |
| 已完成历史 | 保存但入口未明确 | 主窗口提供只读已完成区域 |
| 悬停冻结 | 语义不清 | 真实截止时间不改，最长 60 秒完成保护期 |
| 数据诊断 | 未定义 | 本地 7 天匿名化日志，用户主动导出 |
| 无刘海设备 | 可降级使用其他功能 | 明确不支持，启动提示后安全退出 |
| 工具链 | Swift 5.9+，并发模式未固定 | Swift 6 + Strict Concurrency Complete，UI 显式 MainActor |
| 外部依赖 | 多个候选封装 | 仅 KeyboardShortcuts 3.0.1，其他能力使用系统框架 |

## 19. 内测反馈问题

每轮内测至少收集以下反馈：

1. 一天中是否会自然注意到刘海水滴，而不需要主动打开任务列表？
2. 是否能仅凭位置、颜色和形态判断哪个任务更紧迫？
3. 8 个任务同时显示时，是否能准确悬停到目标任务？
4. 水滴是否造成分心、遮挡或焦虑？出现在哪些应用或场景？
5. 快捷时间选项是否覆盖日常任务，缺少哪些高频选项？
6. 完成汇入鱼缸是否提供了足够但不过度的正向反馈？
7. 时间废墟和 10 次召回是否有记忆点，还是只造成烦躁？
8. 是否遇到任务丢失、时间错误、状态跳变或窗口无法关闭？
9. 是否愿意继续保持应用常驻，并在下一周继续使用？

若多数用户不会自然关注水滴，或认为水滴持续造成干扰，即使技术指标全部通过，也不能直接进入完整 MVP，应先重新评估核心产品假设。
