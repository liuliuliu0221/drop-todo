# M4B 验证记录（2026-08-21）

## 1. 结论

M4B 的自动化可靠性门禁、当前基准机的 30 分钟性能门禁和兼容性采集工具已经完成。当前 Mac 上的快捷输入、CPU 和内存指标达到文档门槛，Release 全量回归无失败。

本记录不把单机结果扩展为完整兼容结论。macOS 13、第二种刘海尺寸、外接屏、镜像、Reduce Motion、无刘海阻断、全屏应用组合和三名用户连续 7 天使用仍缺少对应实机证据，因此 M4B 尚未满足完整退出条件，也不能据此进入 M4C 放行。

## 2. 验证环境与场景

- 机型：Mac17,3（MacBook Air），arm64；
- 系统：macOS 26.5.2（25F84）；
- Xcode：26.6（17F113）；
- 显示：单个内置刘海屏，1470 × 956 pt，2×，顶部安全区 32 pt；
- 镜像：关闭；
- Reduce Motion：关闭；
- 基准数据：8 个 active 任务，刘海水滴和鱼缸保持显示，无用户交互；
- 稳态：Release 构建预热 15 秒后连续采样 1800 秒，每 5 秒采样一次。

兼容性原始快照位于 `.m4-results/20260821-125230-performance-full/compatibility/compatibility.json`。

## 3. 本阶段实现

- 为 `TaskStore` 增加可注入的原子写入边界，使权限拒绝、磁盘空间不足等失败可以确定性复现，同时保持生产路径仍使用原子写入；
- 增加截断主文件、主备双损坏、权限写失败、磁盘满写失败测试，校验原始字节和内存快照不被失败写入覆盖；
- 增加快速重复完成、焚毁和清除操作测试，校验并发终态修改只有一次生效且重载后一致；
- 复用并纳入门禁的 100 次混合修改与 20 次重载测试；
- 增加 8 任务 Release 性能夹具，使用独立沙盒临时存储并通过标准输出发送就绪标记，不记录任务标题；
- 增加 `⌥T` 到输入框完成聚焦的端到端测量，Release UI 测试执行 20 次并断言 P95；
- 将刘海液体位图从独立 10 fps Metal→CPU 回读改为随状态/时间布局更新重绘；鱼缸稳定态使用 4 fps，撞击的 1 秒短动画使用 30 fps；
- 增加性能、可靠性和兼容性脚本，并让 Instruments 按明确 PID 附着，避免 `xctrace --launch` 遗留进程和附着旧实例；
- 自动采集机型、系统、Xcode、屏幕几何、安全区、刘海、镜像和 Reduce Motion 状态。

## 4. 性能结果

| 指标 | 门槛 | 结果 | 判定 |
|---|---:|---:|---|
| `⌥T` 到可输入 P95 | ≤ 300 ms | 49.382 ms（20 次；首开 184.644 ms） | 通过 |
| 30 分钟平均 CPU | ≤ 2% | 1.055% | 通过 |
| CPU P95 | 记录 | 1.900% | 记录 |
| CPU 单样本峰值 | 记录 | 2.6% | 记录 |
| 峰值 RSS | ≤ 150 MB | 74.3 MB | 通过 |
| RSS 首尾变化 | 无持续增长 | 73.9 MB → 55.4 MB，变化 -18.5 MB | 通过 |
| 稳态完整性 | 1800 秒 | 358 个有效样本，进程未退出 | 通过 |

性能证据位于 `.m4-results/20260821-125230-performance-full/`，其中包括 `steady-state.csv`、`summary.md`，以及各 60 秒的 Time Profiler、Allocations、Leaks 和 Activity Monitor trace。四个 trace 均已完成记录并通过 `xctrace export --toc` 导出校验。

Xcode 26 的 Power Profiler 在 macOS 上会明确报错，仅支持 iOS/iPadOS；模板列表也不再提供 Energy Log。因此 macOS 门禁使用 Activity Monitor trace 作为能耗相关替代证据，并保留 CPU/内存长采样。该替代关系仅适用于当前工具链，应在 Xcode 版本变化时复核。

最终快捷输入证据位于 `.m4-results/20260821-m4b-latency-final/latency.xcresult`，原始 20 次样本已导出到同目录 `attachments/`。

## 5. 可靠性结果

Release 可靠性门禁共 73 个测试，73 通过、0 跳过、0 失败。证据位于 `.m4-results/20260821-124617-reliability/reliability.xcresult`。

| 场景 | 自动化证据 | 状态 |
|---|---|---|
| 100 次创建及混合终态修改、20 次重载 | `oneHundredMixedMutationsSurviveTwentyReloads` | 通过 |
| 50 个并发创建 | `concurrentCreatesDoNotLoseWrites` | 通过 |
| 主文件截断与 previous 恢复 | `truncatedPrimaryRecoversPreviousAndPreservesTruncatedBytes` | 通过 |
| 主备文件双损坏 | `corruptPrimaryAndBackupAreBothPreservedWithoutCreatingEmptyStore` | 通过；未静默创建空库 |
| 权限拒绝与磁盘满 | 两个注入写失败测试 | 通过；磁盘和内存状态均不变 |
| 完成、焚毁、清除快速重复操作 | `rapidRepeatedTerminalMutationsRemainConsistent` | 通过 |
| 跨月、跨年截止时间 | `tomorrowHandlesMonthEndAndYearEnd` | 通过 |
| 退出重启后数据保留 | Release UI 重启测试 | 通过 |

M4B 修改后的 Release 全量门禁也已复跑：`.m4-results/20260821-135019/ReleaseTests.xcresult` 共 85 个测试标识，84 通过、1 个按设计跳过、0 失败；浅色和深色启动均通过。跳过项仍是只存在于 Debug 的跨窗口动画调试入口，该路径已有 M4A Address Sanitizer 证据。

## 7. 复现命令

```bash
scripts/m4_reliability_gate.sh
scripts/m4_performance_gate.sh smoke
scripts/m4_performance_gate.sh full
scripts/m4_compatibility_snapshot.sh
scripts/m4_quality_gate.sh
```

`smoke` 使用 30 秒稳态和 3 秒 trace，仅用于快速回归；只有 `full` 的 30 分钟结果可以用于性能门槛判定。结果按时间戳写入 `.m4-results/`。
