# M0：工程初始化与核心技术验证

## 1. 阶段目标

建立可持续开发的 Swift 工程，并在投入业务功能前验证四个可能导致架构返工的问题：Metal 液体、全屏刘海窗口、精确点击区域和跨窗口动画。

M0 只使用固定测试数据，不实现正式任务存储。

## 2. 前置输入

- POC 需求与验收 v1.1；
- MVP 总体架构与工程规范；
- 可运行 macOS 13+ 的 Xcode；
- 至少一台单屏刘海 Mac；
- Apple Developer Team 可暂缓到 M4，M0 使用本地开发签名。

## 3. 工作包

### 3.1 M0A：工程基线

- 将 Xcode 模板工程统一重命名为 `WaterDropTodo`：project、app target、scheme 与 Swift module 同名；产品显示名为“水滴待办”，Bundle ID 为 `com.liuliuliu.WaterDropTodo`；
- 建立 `WaterDropTodo`、`WaterDropTodoTests`、`WaterDropTodoUITests` 三个 Target；
- Deployment Target 设为 macOS 13.0，仅构建 arm64；
- 使用 Swift 6 语言模式和 Strict Concurrency `Complete`，不启用全局默认 MainActor；UI、AppKit 与窗口协调入口显式标注 `@MainActor`，跨隔离数据满足 `Sendable`；
- 单元与集成测试使用 Swift Testing，UI 与性能测试使用 XCTest；
- 打开 App Sandbox，并启用 User Selected File 的 Read/Write 权限；
- 接入 SwiftLint/SwiftFormat 时必须固定版本，未接入也不得阻塞 M0；
- 建立 Debug、Release 配置；
- 建立 `AppEnvironment` 和 `WindowCoordinator`；
- 设置 `LSUIElement = true`；
- 启动时检测内置刘海；无刘海设备显示“不受支持”提示并退出；
- 更新 README，写明 Xcode、构建和测试命令；
- `.gitignore` 增加 Xcode 用户数据、DerivedData 和签名产物规则。

建议首个 CI 命令：

```bash
xcodebuild \
  -project WaterDropTodo.xcodeproj \
  -scheme WaterDropTodo \
  -destination 'platform=macOS' \
  test
```

### 3.2 M0B：刘海窗口与精确命中 Spike

#### 3.2.1 刘海与窗口

实现最小 `DisplayPolicy` 和 `NotchGeometry`：

- 从 `NSScreen` auxiliary areas 和 safe area 获取刘海几何；
- 创建透明、无阴影、不抢焦点的 `NotchRenderPanel`；
- 配置全 Space 和 full-screen auxiliary 行为；
- 支持显示、隐藏和屏幕变化重定位；
- 无刘海设备在启动阶段提示不受支持并退出，不进入应用主流程；
- 外接显示器、镜像或合盖仅使用外接屏时，暂停刘海窗口及相关交互，但应用、任务与主窗口继续运行；
- 审核并实机验证 `NSPrefersDisplaySafeAreaCompatibilityMode = false`，确保全屏时不会被系统兼容模式整体下移。

实测场景：普通桌面、Safari 全屏视频、Keynote、Xcode 全屏、Finder 全屏和至少一种游戏或高刷新窗口。

#### 3.2.2 命中与点击穿透

- RenderPanel 全程忽略鼠标；
- 创建最多 8 个最小透明命中 Panel；
- 命中 Panel 跟随布局快照移动；
- 重叠时通过 `HitTestCoordinator` 选择最近中心；
- 悬停时显示调试边框；Release 不显示；
- 刘海周围透明区域点击必须到达下层应用；
- 不申请辅助功能或输入监控权限。

如果小型命中 Panel 方案在实机不可行，必须形成 ADR 后再评估其他方案，不能退回整块透明窗口拦截鼠标。

### 3.3 M0C：Metal 液体 Spike

交付可调参数的演示场景：

- 一片连续液面；
- 1、3、8 个 metaball 水滴；
- 清透浅蓝到深蓝、黑色的进度变化；
- 单水滴悬停放大且不断开；
- 拉长、断开和坠落；
- Debug 面板可修改半径、阈值、扰动、颜色和间距。

CPU 每帧只提交固定上限 8 个水滴的参数，不生成逐像素位图。

### 3.4 M0D：跨窗口动画与验证 Spike

- 创建忽略鼠标且不成为 key window 的 `TransitionOverlayPanel`；
- 从刘海测试点直线移动到右下角测试鱼缸点；
- 从普通 SwiftUI 列表行转换屏幕坐标后移动到鱼缸；
- 动画期间切换窗口焦点，验证不抢焦点；
- 动画期间改变屏幕配置时安全取消；
- 验证 backing scale 和不同屏幕分辨率下落点误差。

## 4. 测试与测量

- Metal 1、3、8 水滴帧时间；
- 30 分钟稳态 CPU、内存和 GPU 观察；
- 100 次悬停进入/离开没有残留 Panel；
- 100 次跨窗口动画没有明显窗口泄漏；
- 透明区域连续点击菜单栏和下层应用无误拦截；
- 全屏切换 20 次后窗口位置正确。

M0 不要求最终视觉质量，但必须记录性能基线和失败机型。

## 6. 退出条件

- [ ] Debug 和 Release 均可编译；
- [ ] project、target、scheme、module、显示名和 Bundle ID 均符合命名基线；
- [ ] macOS 13.0、arm64、Swift 6 Complete Concurrency 与 App Sandbox 配置生效；
- [ ] Swift Testing 单元/集成测试和 XCTest UI/性能测试 Target 均可运行；
- [ ] 无刘海设备会阻断启动；外接、镜像和仅外接屏模式会暂停刘海功能且主应用可继续使用；
- [ ] 8 个水滴形态连续并可单独命中；
- [ ] 非命中区域点击穿透；
- [ ] 全屏场景达到 POC 预期或已有明确降级；
- [ ] 两类直线动画起点都能准确转换到鱼缸目标；
- [ ] 稳态渲染不永久以 60fps 空转；
- [ ] 不需要更换 Metal 或多 Panel 窗口拓扑；
- [ ] 所有阻断问题已有 ADR 和结论。

- 正式鱼缸视觉；
- 废墟和召回；
