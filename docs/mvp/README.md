## 1. 使用方式

本目录是 MVP 的执行级技术文档。开发开始前先阅读[总体架构与工程规范](./00_总体架构与工程规范.md)，然后按 M0～M4 顺序推进。后续阶段不得绕过前置阶段的退出条件。

需求优先级如下：

1. 《水滴待办 POC 需求与验收 v1.1》中已经确认的规则；
2. 本目录中的技术设计与阶段验收；
3. 《水滴待办 PRD v2.0》；
4. 《技术选型报告 v1.0》。

若下游文档与上游已确认规则冲突，以更高优先级为准并记录 ADR，不允许在代码中静默选择。

当前工程命名基线：仓库目录为 `Drop_todo`，Xcode 工程、Target、Scheme 和 Swift 模块统一为 `WaterDropTodo`，应用显示名称为“水滴待办”，Bundle ID 为 `com.liuliuliu.WaterDropTodo`。

## 2. 当前仓库基线

当前仓库已经通过 Xcode 建立原生 macOS App 模板，但仍保留模板名称：

```text
Drop_todo/
├── Drop_todo.xcodeproj
├── Drop_todo/
└── docs/
```

模板尚不代表 M0A 完成。M0A 必须将 project、target、scheme 和 module 统一为 `WaterDropTodo`，添加测试 Target，并应用 macOS 13、arm64、Swift 6、沙盒和应用生命周期基线。

## 4. MVP 固定范围

以下决定不得在开发中自行改变：

- 事件与时间分开输入，不做自然语言解析；
- 时间选项为 30 分钟后、1 小时后、2 小时后、今晚 20:00、明天 09:00、自定义；
- 默认快捷键为 `⌥T`；
- 刘海最多显示 8 个最近截止任务；
- 液体使用原生 Metal fragment shader；
- 完成水滴沿直线飞入鱼缸；
- 金鱼平时低动态，落入时短时快速游动；
- 自动遵循 macOS“减少动态效果”；
- 任意多显示器或镜像环境下暂停刘海窗口；
- 合盖仅使用外接屏时暂停刘海窗口；
- 无刘海设备启动时提示不支持并退出，不提供列表或顶部胶囊降级；
- App Sandbox 保持启用，用户主动选择的导出位置允许读写；
- 领域、存储和窗口代码使用 Swift 6 严格并发检查；
- 单元/集成测试以 Swift Testing 为主，UI 与性能测试使用 XCTest；
- 唯一第三方依赖为精确锁定的 `KeyboardShortcuts 3.0.1`；
- POC/MVP 内测阶段不接入 Sparkle；
- 不发送通知、不播放声音、不自动上传数据；
- 分发使用 Developer ID 签名、公证 DMG，用户手动安装新版本。

## 5. 全局 Definition of Done

任何开发任务只有同时满足以下条件才算完成：

- 行为符合 POC 文档和当前阶段验收；
- 关键领域逻辑具备单元测试；
- 时间、UUID、文件系统等不确定依赖可注入；
- 没有新增编译警告、线程检查器错误或明显资源泄漏；
- 失败路径向用户提供可理解反馈，向本地日志写入可诊断信息；
- 不把任务名称写入默认诊断日志；
- 跨版本数据修改包含迁移或兼容说明；
- 手工验收步骤已经执行并记录机型与 macOS 版本；
- 相关技术决策和阶段清单已同步更新。

## 6. 变更控制

以下变化必须先更新需求或 ADR，再修改实现：

- 改变任务状态语义或截止时间规则；
- 改变可见水滴上限；
- 增加后台网络、遥测、通知或权限；
- 更换 Metal 渲染、窗口拓扑或持久化方案；
- 扩大到多显示器刘海渲染、云同步或自动更新；
- 修改最低系统版本或发行架构；
- 任何可能导致已有内测数据无法读取的 Schema 变化。

ADR 建议放置在 `docs/mvp/adr/`，命名为 `NNNN-简短标题.md`，内容至少包含背景、决定、备选方案、影响和回滚条件。
