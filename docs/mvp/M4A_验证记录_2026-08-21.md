# M4A 验证记录（2026-08-21）

## 1. 结论

M4A 自动化质量门禁通过。Release 全量测试、三 Target 构建、静态卫生检查、Thread Sanitizer 和 Address Sanitizer 均通过；Release 动画调试入口按设计不进入产物，由 Debug + Address Sanitizer 专项覆盖。

本记录只确认 M4A。M4B 的性能、能耗、破坏性测试和兼容性矩阵，以及 M4C 的签名、公证、DMG 和内测运行不在本次完成范围内。

## 2. 验证环境

- 设备：MacBook Air，arm64；
- 系统：macOS 26.5.2（25F84）；
- Xcode：26.6（17F113）；
- Swift：6.3.3；
- 工程：`WaterDropTodo.xcodeproj`；
- 共享 Scheme：`WaterDropTodo`。

应用 Target 继续支持 macOS 13.0。由于 Xcode 26 自带 XCTest、Testing 和 XCUIAutomation 框架最低为 macOS 14，两个测试 Target 的部署版本设为 macOS 14.0，以消除与应用代码无关的测试框架链接警告。

## 3. 已实现的门禁

- Debug 与 Release 均启用 Swift Strict Concurrency `Complete`，Release 将 Swift 警告视为错误；
- 建立包含应用、单元测试和 UI 测试的共享 Scheme；
- 固定 `KeyboardShortcuts` 3.0.1，并由卫生脚本校验解析结果；
- 增加 `TaskDataValidator`，在加载、恢复和保存前校验重复 ID、状态时间戳和召回引用；
- 数据测试覆盖当前 Schema、未知字段、主文件损坏后的 previous 恢复、语义损坏、拒绝保存，以及不支持 Schema 且无备份时保留原文件等待未来迁移；
- 本地日志保留窗口限制为 7 天，并覆盖持久化测试；
- Release 通过条件编译移除液体和跨窗口动画调试面板，并对产物执行可识别调试标题扫描；
- UI 测试使用独立临时存储、任务系统就绪门控和确定性截止时间夹具，避免多用例会话中的 SwiftUI Picker 可访问性快照波动；
- `check_release_hygiene.sh` 校验构建设置、共享 Scheme、依赖锁定、资源 JSON、敏感信息、任务标题日志和 Debug 面板隔离；
- `m4_quality_gate.sh` 执行 Release 全量测试和产物扫描；
- `m4_sanitizer_gate.sh` 分别执行 TSan 核心测试与 ASan 窗口/动画 UI 测试；
- `.m4-results/` 被忽略，避免将体积较大的 DerivedData 和 xcresult 误提交仓库。

## 5. 复现命令

```bash
scripts/m4_quality_gate.sh
scripts/m4_sanitizer_gate.sh thread
scripts/m4_sanitizer_gate.sh address
```

结果目录带时间戳生成在 `.m4-results/`。Release 测试使用 `ENABLE_TESTABILITY=YES` 仅供 `@testable import` 测试构建。M4C 启用 Hardened Runtime 后，测试宿主还会使用 `ENABLE_HARDENED_RUNTIME=NO`，避免 ad-hoc 签名的单元测试 bundle 被正式运行时的库验证拒绝；正式 Archive 仍强制启用 Hardened Runtime，并由 M4C 产物验证脚本检查签名 flags。测试参数都不会进入 M4C 的正式 Archive。
